# What's Poppin: Crucible implementation plan

Date: September 7, 2026. Baseline: 17998d8. Status: proposed implementation plan; independent audit recorded in [AUDIT.md](AUDIT.md). This file records the plan; implementation has now begun in a separate P00 worktree, tracked under phases/P00/STATUS.md there. Native scope is a later amendment to the originally audited planning snapshot. It does not authorize or perform a production deployment, charge, live crawl, or contact with users.

The product is a shared destination for local event discovery, event promotion and agents acting for organizers or attendees. Travelers should quickly find worthwhile activities nearby, and optionally someone compatible to attend with. Deterministic collection builds broad coverage; a small OpenRouter-powered browser worker handles exceptions and nightly upkeep.

This document supersedes conflicting scope/pricing assumptions in the old specification for the planned work. [CLAIMS.md](CLAIMS.md) distinguishes existing source, broken integration and unverified behavior. [RESEARCH.md](RESEARCH.md) records protocol and review-system research. [GATES.md](GATES.md) certifies this planning delivery only, not the future product.

## Non-negotiable product constraints

- User subscription: USD 1 per month. An organizer pays a small listing fee; its amount must be set before live billing. Imported source listings are not billed to uninvolved organizers. Paid placement must not secretly change organic relevance or friend matching.
- Reviews contain no numerical score. No stars, reputation totals, public or hidden global person scores, leaderboards, popularity tiers, or social-credit-style profiles. Feedback is private input for better reciprocal pairing.
- Agents can publish/manage events for an authorized organizer and discover events for an authorized user. A2A 1.0 is the proposed external protocol; ordinary HTTP operations remain the shared application contract. Optional MCP is deferred until a target client requires it, not substituted for the requested A2A path.
- Collection covers Facebook, Meetup, clubs, bars and local city pages through source-specific permitted access. Unsupported access stays visible in the source registry and review queue; it is not silently counted as covered.
- First complete and connect features (P00-P08). Then run the broader correctness/security remediation and release pass (P09-P10). Necessary authorization, privacy, input validation and cost controls are part of each feature from its first connection; they cannot safely wait for the final pass.

## Delivery method

Codex builds; Claude Opus at high effort audits. Work sequentially in isolated worktrees, one reviewable logical change at a time. Preserve Next.js, TypeScript, Supabase/Postgres and useful existing components. Keep the existing Next.js website and backend. The user now requires iOS App Store and Android apps: add one Expo/React Native mobile client for both stores, using the same authenticated HTTP contracts, without cross-package source sharing initially. Do not replace the website or duplicate backend rules. Native delivery is required, not an optional later product.

Per-phase ledgers live in docs/crucible-20260907/phases/Pxx/GATES.md using CHECK/EXPECT/EVIDENCE, distinct from this planning ledger. For every phase: author its runnable acceptance ledger and fail-first probe before code; demonstrate the probe fails on the defect or a planted bad fixture; implement the minimal complete change; run the phase gate; have Opus inspect intent, diff and gates independently; resolve findings and rerun after the last edit. The author is not a verifier of their own artifact. The auditor reruns the underlying checks directly in its environment. Production release is blocked by any unresolved applicable acceptance gate. Expected failures are baseline evidence, never passing implementation gates.

Use existing Vitest for unit/service tests, a disposable local Supabase/Postgres instance for SQL/RLS, and Playwright for browser acceptance. Native acceptance uses Maestro scripted core journeys on hosted Android/iOS runners; explicitly recorded manual device checklists cover screen readers, permissions and sandbox purchases until reliable automation is demonstrated. Add only the missing test/browser dependencies that these checks require. Fixtures use fake users, recorded source documents, a frozen clock, fake geolocation, fake model responses and processor test mode. A live source/provider smoke check supplements hermetic tests; it does not replace them.

## Data model first

Keep events and venues, but reconcile the schema and generated types before extending them. Add fields/tables only in the owning phase:

| Owner | Data | Required invariant |
| --- | --- | --- |
| P01 | Public profile projection; private preferences/location; one interaction vocabulary | Public event browsing cannot read precise user locations, private interests or reviews. User-scoped requests never share server session state. |
| P01/P03 | Organizer identity linked to an authenticated profile; ownership_claims for imported events | P01 supports self-owned listings without a new organization hierarchy. P03 verifies imported-event claims by source-controlled contact/domain evidence or recorded human review. A claim cannot seize an event merely by matching its title or supplying an organizer ID. |
| P03 | sources, source_snapshots, source_event_links, event revisions; canonical event and occurrence identity | Multiple source records may refer to one event occurrence; recurring dates remain distinct. Source links, extraction version and last-checked time remain traceable. |
| P03 | Canonical venues, venue_source_links, explicit city and venue IANA timezone | Source-specific venue aliases resolve to one venue or a review item. No silent Austin/TX defaults for imported locations. |
| P04 | subscriptions, listing_orders, webhook_receipts | Server-verified entitlement and idempotent billing; no imported-listing fee. No card details stored. |
| P05 | ingestion_jobs, review_items, audit entries | Durable bounded work, leases, retries, evidence and reversible updates. A model cannot bypass validation or its source scope. |
| P06 | delegated agent grants and task ownership | Revocable least privilege tied to a principal; event writes and payment spend require separate authority. |
| P08 | age attestation, matching opt-in, event-specific invitations, encounters, private feedback, blocks and safety reports | Mutual consent, private feedback, no person-level rating field; blocks override all matching and messaging. |

Use an integer minor-unit amount and currency consistently for money. Audit existing prices before any conversion; never blindly multiply already-stored cents. Store event timestamps in UTC plus the source/venue IANA timezone and original local representation. Recurrence and reschedules need occurrence identity, not title-based matching. Missing date/location/status/price is unknown, not fabricated. A quarantined-unit event is labelled price-unknown and excluded from price-bounded discovery filters; it never matches free or under-budget filters. P02 acceptance includes unknown-price, genuinely free and known paid events as controls.

### P03: Build deterministic ingestion and canonical event storage

Dependency: P01-P02. Own source registry, canonicalization, source adapters and ingestion migrations. Seed the pilot city's registry with venue/city calendars and explicit access-dependent Facebook/Meetup entries. Use fetch with deadlines, conditional requests, response-size limits and per-domain rate limits. Prefer API/feeds, JSON-LD Event and iCalendar, then deterministic HTML selectors; use a browser only when rendering is necessary.

Start with a source-access spike before building those adapters: prove the actual Meetup query/scopes available to the intended account, identify the authorized Facebook route if any, and capture at least one permitted venue/city feed fixture. An unavailable source is access_pending with an owner and next action, never a pretend successful adapter. This is an early scope checkpoint for source coverage, not a reason to postpone all other ingestion.

Validate and normalize to one event contract. Deduplicate source IDs/URLs first, then candidate matches by venue, time and normalized title. Ambiguous matches go to review, never automatic destructive merges. Preserve multiple provenance links and versioned revisions. A verified organizer owns its submitted fields; imported updates cannot overwrite organizer-locked fields. Explicit authoritative cancellation can change status; a transient 404 or missed crawl only marks source freshness/availability. Recurring occurrences, rescheduled events, multi-day events, online/hybrid events and venue changes require explicit fixtures.

Acceptance: replay fixtures from all supported adapter types twice without new duplicates; ingest two sources for the same occurrence into one canonical event while preserving both links. Same-title events on different days remain separate. Reordered pages, 304s, malformed feeds, duplicate identifiers and partial failures do not corrupt known records. Cancellation/reschedule updates invalidate discovery caches and embedding work appropriately. DST boundaries and ambiguous local dates resolve by source timezone or enter review. Server-side URL restrictions reject local/private destinations and unsafe redirect chains while a permitted URL succeeds.

Also prove differently named aliases for one venue resolve to one canonical venue or enter review, and two similarly named venues in different cities do not merge. An unverified claimant cannot edit an imported event; verified claims can lock authorized fields and revoke prior delegated access. The verified claim's source evidence and reviewer are recorded.

P03 extends P02's takedown acceptance to provenance: removing one disallowed source preserves independently permitted source records without silently restoring hidden content.

### P04: Wire the two payment flows

Dependency: P02-P03. Own subscription and listing checkout, entitlement service and processor webhooks. USD 1/month is the user price. Treat the organizer listing fee as configuration that must be explicitly populated before live listing checkout is enabled. Default proposal: one charge for the initial organizer-submitted listing; ordinary corrections and cancellation do not charge again. Imported events remain searchable and attributable without charging their organizer; claiming ownership needs verification and does not retroactively create a bill.

Give agents a price quote and a draft operation; publication that incurs a fee requires an approved quote or an explicit bounded spending grant. Use processor-hosted checkout and verified webhook state. Subscription cancellation, refunds, failed renewals and listing-payment failures have explicit states. Users can always manage billing, privacy, blocks and reports even after subscription expiry. Do not create a wallet, tradable credit or custom payment protocol.

Acceptance: test-mode $1 subscription activates only on verified processor state, cancels correctly and expires at the paid-through boundary. Duplicate/out-of-order/replayed webhooks do not double-charge, duplicate publication or restore revoked entitlement. Payment-success/database-failure recovers through reconciliation. Unpaid organizer drafts remain unpublished; an imported event never creates a payment. Listing edits do not charge again. A discovery-only agent cannot publish or spend.

Entitlement proposal: public event-detail/source previews support sharing; paid subscription enables personalized discovery and Find a Friend. Keep all protected operations server-gated, including direct agent requests. Previously accepted meeting coordination remains available through its expiry even if a subscription lapses, along with safety/privacy/billing controls. P04 owns billing-linked account deletion and minimal retained receipt rules; never retain card data. Final live product gates require a configured listing amount, processor account and budget, but the test-mode phase uses a clearly labelled fixture listing price.

### P05: Add the minimal nightly OpenRouter/browser worker

Dependency: P03, with P00 controls. Own worker entry point, small tool loop, review UI and job migrations. One Railway scheduled worker combines dispatch and bounded queue draining, backed by a durable Postgres job table; use a row lease with expiry to avoid overlapping runs. This separate process handles browsers so Next.js requests do not own overnight work. The Railway deployment contract below defines its finite lifecycle. No agent framework, agent swarm or autonomous code editing.

Nightly run: snapshot the due source list; run deterministic fetch/extract; route ambiguous/missing-field/layout-change cases to the model worker; inspect a deterministic sample of otherwise successful updates; validate proposed corrections; apply allowed low-risk revisions; queue conflicts and consequential ambiguous changes for a human; refresh dependent search/embedding records; publish an operations summary. New dates, cancellation or venue changes inferred only from an ambiguous image require review. Human review uses before/after fields, source URL, retrieval time and screenshot evidence, with apply/reject/revert actions and an audit trail.

Sampling is a bounded part of the requested nightly checking: perform deterministic consistency checks first, then at most one budgeted visual spot-check per enabled city per night initially. If the shared daily cap cannot cover it, record skipped_budget and put the unsampled outcome in the summary. Do not label it checked. No second model is required for routine low-risk extraction.

Tools: fetch an allowed page, read bounded rendered text, capture a cropped screenshot, propose a structured event patch and request human review. The model has no arbitrary shell, unrestricted browser profile, payment tool or direct database mutation. The host validates tool arguments, allowed hosts, redirect destinations and network egress, including browser subresources and IPv6/local-network destinations. External page text and screenshots are untrusted data, not instructions. Use an isolated browser context with no personal cookies; licensed source credentials remain host-managed and source-scoped.

Initial proposed job limits: 8 tool calls, 2 screenshots and 120 seconds per exception job; single browser concurrency. Configure a hard daily monetary cap before enabling OpenRouter, reserve budget before calls, and stop dispatch on budget exhaustion. Pin a model/provider combination supporting tools and images; permitted fallbacks must preserve data-policy and budget requirements. Cache extraction by source content hash and parser/prompt version. Never send private friend feedback or precise user GPS to this ingestion agent.

Scheduling proposal: one run per enabled city's local date in its configured overnight window; compute next execution from IANA timezone, with a unique run key so DST or retries cannot double-run. Retry transient failures with bounded backoff, respect Retry-After, resume checkpoints after crashes, and put exhausted work in review. Expired leases, missed scheduled ticks and stuck worker runs must be observable. Screenshots are private operational evidence with a short retention policy, not permanent scraped archives.

Acceptance: a fixture layout change defeats the deterministic adapter; the controlled visual/tool response supplies supported fields and produces a reversible revision. A fabricated date, prompt injection, invalid JSON, unsafe URL, forbidden action, timeout, unavailable provider, repeated tool call, exhausted budget and malicious screenshot never bypass policy. Crash/restart and overlapping dispatchers may execute work again but cannot duplicate a committed revision for the same job/event/source-version tuple. Every due source ends with an explicit outcome, including blocked, access_pending and skipped_budget; skipped_budget must never be reported as checked. A human can inspect and revert a candidate update; the audit log identifies actor, evidence and prior/new versions. Verify one screenshot-enabled provider smoke test before enabling live nightly operation.

Clarification: execution is at-least-once with idempotent committed effects, not a claim of exactly-once model/browser execution. A stale lease holder cannot commit after another worker acquires the job; use a fencing/version check inside the update transaction. Cancellation and daily spend reservations are checked again before each side effect. Test the lease-expiry race and duplicate completion callbacks.

Dependency: P01-P04. Own shared event HTTP contract and A2A adapter. Use the official JavaScript SDK after a small interoperability spike confirms the chosen released version and runtime. Publish a truthful Agent Card and structured operations for search/get event, draft/submit/update/cancel an owned event, quote publication, and get task status. Define explicit scoped user and organizer grants with expiry, revocation, task ownership and idempotency. Never infer authority from a model's self-description or a payload user ID.

Authentication proposal: standard OAuth/OIDC delegated user grants for personal assistants; registered source/service clients get narrower service credentials. Keep transport auth separate from application authorization. Task polling is sufficient initially; do not add arbitrary callback delivery or federation. Short deterministic requests need not invoke an LLM. A2A is an adapter over the same service and schemas as the UI, not a second business implementation. An MCP adapter remains a later interoperability option.

Acceptance: an independent A2A client acting for organizer A submits and updates a fixture event; another independently authenticated client finds it for user B with requested location/time/interest constraints. Both use the published protocol, not private hardcoded calls. Replay preserves one event and one charge authorization. Expired/revoked/wrong-audience tokens, cross-user task IDs, forged ownership and excess spend are rejected. Partial work resumes or cancels according to advertised task capabilities. Required protocol conformance and version mismatch behavior pass the SDK's supported checks.

P06 entitlement/privacy acceptance: an unentitled agent receives public previews only and is denied personalized discovery and Find a Friend; entitled fixture principals succeed once the owning feature is available. P08 reruns this through A2A when friend operations are connected. No response may expose another participant's precise location or non-consented private contact. Test direct agent requests as well as UI requests.

Named initial interoperability target: the official a2a-js client in a separate test process, with independent organizer/user credentials and no imports from the server's business implementation. Pin client/server versions and record the binding in the spike. Add per-grant rate/request quotas and 429/Retry-After behavior. Revocation cancels queued/in-flight work and is rechecked before committing side effects; test revoking between task acceptance and publication. This adapter remains required even if optional MCP is deferred.

### P07: Connect reliable personal discovery

Dependency: P02-P03; paid entitlement from P04 and agent parity from P06 for the full journey. Own event relevance, onboarding and conversational search. Ground AI recommendations in canonical event IDs and validated filters. Apply location, local time, budget, accessibility needs volunteered by the user, cancellations and availability before ranking. Use shared event embeddings and deterministic filtering/ranking for routine discovery; model calls clarify ambiguous requests, not every page refresh. Explain suggestions using actual event metadata. Handle cold starts with user-selected interests and local upcoming events.

Acceptance: a traveler changing city sees that destination's upcoming events, not the profile's old city. A new user receives useful fixture results without history. A model-invented event ID or impossible time is rejected. Cancelled/expired events do not reappear from recommendation caches. Text and supported voice paths reach equivalent query constraints; unsupported voice has a usable text path. The website, iOS app, Android app and agent interface return compatible results under the same principal and query. A provider outage still allows deterministic search.

P07 owns conversation integrity now: server stores trusted conversation state; client submits a new bounded user turn, not a replayed roles array. Test client-injected system/tool messages cannot replace server instructions or trigger privileged actions. Cost gate: ten repeated identical deterministic searches make zero chat-model calls; one ambiguous query may make at most one clarification call before asking the user again. Enforce a configured per-user daily AI quota and shared interest-embedding cache; increasing candidate event count must not regenerate the same user-interest embedding per event.

### P08: Build Find a Friend and private feedback

Dependency: P01, P04 and P07. Own matching opt-in, invitations, event-specific coordination, blocks/reports and private feedback. Proposed initial boundary is adults only, public events and explicit opt-in. P08 owns a private minimum-age attestation with policy version/time, required server-side before matching opt-in, candidate inclusion or invitations; this is self-attestation, not verified identity or proof of age. Test absent, declined and revoked attestation on UI and agent paths; confirm the age policy before real-user pilot. Default location visibility is city/event-level. Exact GPS is used transiently for event discovery and never exposed to another participant or their agent.

Start with eligibility rules: same city and event/compatible time, active consent, mutual volunteered preferences, no block, no outstanding incompatible invitation, and availability. Rank eligible pairings by shared event interests and both participants' stated interaction preferences. Do not train a complex model before collecting consensual feedback. Do not persist any globally comparable measure of a person's quality. Internal contextual relevance calculations are not user review ratings and must not be exported as numeric person-fit labels.

Invitation states: proposed, accepted by one side, mutually accepted, declined, expired, cancelled and completed. Share coordination messages only after mutual acceptance; implement a small event-scoped conversation with rate limits, report/block and expiry. Recheck consent and blocks on reads and writes, not only at match generation. Event cancellation cancels the meeting invitation and offers alternative event discovery. No GPS stalking, background tracking or stranger-accessible people map.

P08 owns an in-app invitation/message inbox with unread state and expiry notices. A recipient returning later can discover and respond to an invitation without both browsers being open. Background push feeds are not required for this first version. Account export/deletion extends P01 to private feedback, derived matching state and messages, preserving the other participant's rights without exposing their private responses. P08 also defines retention/appeal rules for the separate safety-report store before a real-user pilot.

Feedback opens only for a mutually accepted encounter after the event, with attendance confirmation; nonattendance is a separate outcome and never a character rating. Ask categorical questions such as "Meet again: yes / different activity / no preference / no" and "Next time I would prefer: quieter setting / more conversation / smaller group / similar activity" plus an optional private note. Participation is optional. No numeric rating fields, stars or person scores appear in review forms, storage, API responses, logs or exports; ordinary identifiers/timestamps and event-relevance calculations are not review ratings. Private notes remain private; do not send them to OpenRouter by default.

Each author's feedback refines that author's contextual preferences and the author's pair-specific meet-again choice. It does not label the other person as inferior or penalize their matches with everyone else. Keep responses independent and never show them to the other party, even after a submission window closes. A user's explicit "do not match us again" applies immediately; blocks and safety reports apply immediately and separately from any review window. No feedback and declined invitations have no negative reputation effect.

For an eligible pair, ranking inputs are limited to each participant's own volunteered/contextual preferences, their shared event/availability and their pair-specific choices. Incoming feedback about either participant from unrelated people is excluded, including on-the-fly aggregates, learned reputation embeddings and indirect acceptance-rate features. Safety eligibility decisions are a separately audited gate, never a hidden rank. Required counterfactual: hold the pair's preferences and event fixed, add negative meet-again outcomes about candidate B from unrelated users, and prove B's rank for A is unchanged. Repeat with positive outcomes and cancellation/nonresponse history to catch disguised popularity boosts as well as penalties.

Use a versioned deterministic matching policy first. Keep source feedback records so a user can edit/delete/reset personalization and invalidate derived preferences. Limit repeated feedback from the same encounter/pair from dominating preferences. Human-reviewed safety decisions have their own evidence, access controls and appeal path; a malicious review cannot automatically ban someone. Explanations mention shared interests, never another person's private feedback.

Acceptance: two compatible opted-in adults can mutually accept and coordinate at an event; unilateral acceptance reveals no private contact or exact location. Decline, expiry, event cancellation, block and revoked consent stop contact and future pairing. Only encounter participants can submit one editable private feedback record; third-party, duplicate, fabricated and pre-event submissions fail. Seed numeric-rating/global-person-score canaries and ensure the schema, API, UI and telemetry checks catch them before verifying the real absence. Feedback changes the author's next contextual pairing in a controlled fixture without lowering the subject's standing with other users. Deletion/reset removes its derived effect. Cold-start, sparse feedback and nonresponse do not create penalties. Test protected-attribute/proxy leakage and abuse cases; pilot outcomes assess pairing quality without rating people.

### P09: Systematic bugs and security remediation

Dependency: P01-P08 connected in isolated staging. Own a bounded triage queue across the now-real flows, not a rewrite. First fix reproducible crashes/data corruption, authorization/ownership leaks, injection and money errors; then race conditions, performance, accessibility and reliability defects. Recheck all C01-C18 against the finished behavior and remove stale claims from ordinary project docs.

Audit every route/tool/SQL function using actual authenticated/anonymous/service principals. Cover RLS and public profile projections, service-role exposure, CSRF and cookie/token handling, model-message role spoofing, HTML/URL injection, SSRF and browser egress, AI spending quotas, webhook replay, task replay, review privacy, blocks and messaging abuse. Review SECURITY DEFINER functions and executable grants rather than treating RLS file presence as proof. Audit dependencies at the exact locked versions and patch against primary advisories; do not assume today's versions remain current.

Exercise concurrent event edits, atomic design replacement, duplicate ingestion, paid listing retries, feedback deletion, embedding invalidation, cache expiry and timezone transitions. Recheck hook behavior and stale requests; P00 must already repair the baseline hook-dependency warnings with behavioral tests before enabling mandatory deployment CI.
