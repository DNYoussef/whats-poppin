## Delivery and scope

Codex builds; Opus high independently audits. T2 standard deployment of known upstream components. Original implementation unit: four build rounds and four inspection rounds, including plan inspection; no hidden retries after exhaustion. Existing isolated implementation branch continues. No local Docker. Build and validate containers on GitHub Ubuntu; Railway runs them remotely. Keep configuration and tests in this repository and record exact image digests and source revisions.

Deploy only the current core: Supabase Postgres, GoTrue Auth, PostgREST, an HTTPS API gateway, and private Mailpit for staging email confirmation. Storage, Realtime, Studio and Edge Functions are not connected app dependencies in this unit and are deferred to their owning features. This is a usable core Supabase backend, not a claim that every optional Supabase service is available.

Use upstream Supabase self-hosted/v0.8.0 database bootstrap role/JWT SQL with the documented Postgres 17.6.1.136, GoTrue v2.189.0 and PostgREST v14.12, pinned by registry digest. Use a pinned Nginx gateway image with declarative routing, API-key rejection; GoTrue/PostgREST perform actual JWT verification and role authorization. Never implement password handling or session signing in the gateway. Synthetic credentials are generated locally with cryptographic randomness and stored outside the checkout, then supplied through Railway's variables API without printing values. Keep the database on persistent storage and all services except the gateway private, with no public database proxy. No production credentials, users, provider keys or payment settings are copied.

Gateway contract: /auth/v1/* forwards to GoTrue and /rest/v1/* to PostgREST. Missing/invalid API keys fail closed except the email verification callback and OPTIONS. Bearer headers pass through unchanged; PostgREST uses PGRST_DB_ANON_ROLE for requests without a bearer token. Service-role requests must carry their own verified bearer token. Unsupported routes return 404. Do not log query tokens. CORS initially permits localhost development only. Auth requires email confirmation and delivers only into private Mailpit; live SMTP remains a production prerequisite. Signup/login/refresh/logout/confirmation are verified with synthetic users.
