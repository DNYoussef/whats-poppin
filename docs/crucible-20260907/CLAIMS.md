## Method and limits

The installed codebase-understand framework indexed the repository and produced a structural graph. [Graph evidence](graph-evidence.json) attaches the reviewed source locations to the same qualified graph nodes using the existing join_lens.join implementation. It identifies getSupabase as a shared dependency of many operations. [Capture script](capture-graph.py) is reproducible with the installed connascence Python environment.

The connascence and rlm-docsync lenses are Python-AST-bound. They do not validate this TypeScript application's coupling quality or documentation truth. A previous empty doc-claims result is not a clean bill of health. Runtime tracing is also absent in the substrate. The findings below use direct code/SQL comparisons and [isolated executable probes](probe-baseline.mjs); this is explicitly not a newly implemented automated documentation lens.

## Security interpretation

Source-level evidence warrants fail-closed authentication and privacy work before exposing newly connected paths. It does not justify claiming that an attacker has actually accessed production data. Conversely, a broken path failing before authorization is not a security control. The commented-out migration rollback is not executed SQL; the optional admin override policies are also commented out. The is_admin helper's dependence on editable preferences should be removed before any such override is enabled.

P00 route inventory: api/ai/search-conversation, ai/recommend-events, ai/generate-design, ai/refine-design, embeddings, embeddings/batch, preferences, interactions, recommendations, events/[id]/design and events/[id]/similar need explicit route-level principal/cost/ownership classification. Both cron routes need a mandatory worker secret. api/health can intentionally remain public if its response exposes no secrets. Public read-only event/similar endpoints may be a deliberate product policy; absence of page middleware alone does not prove unauthorized live writes, and configured cron routes already check their secret. The final checklist must be generated from the route inventory during P00 rather than assuming every API route has the same policy.
